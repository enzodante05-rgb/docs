## Workflow overview

All source files are TypeScript (`.ts`) in `~/Documents/_cryptobot_vps/`. Never edit the compiled `dist/` folder directly — it is overwritten on every deploy.

```
Edit .ts files  →  run ./deploy.sh  →  bot restarts on VPS
```

## Local setup

The local mirror of the VPS codebase lives at:

```
~/Documents/_cryptobot_vps/
```

This directory is kept in sync with `/opt/cryptobot/` on the VPS via the deploy script.

## Making changes

<Steps>
  <Step title="Edit TypeScript source files">
    Open any `.ts` file in `~/Documents/_cryptobot_vps/` with your editor of choice.

    ```bash
    cd ~/Documents/_cryptobot_vps
    # e.g.
    code src/strategy.ts
    ```
  </Step>
  <Step title="Deploy to VPS">
    From the local codebase directory, run the deploy script:

    ```bash
    cd ~/Documents/_cryptobot_vps && ./deploy.sh
    ```

    The script compiles TypeScript, rsyncs the output to `/opt/cryptobot/` on the VPS, and restarts the pm2 process.
  </Step>
  <Step title="Verify the deployment">
    Check that the bot started cleanly after the deploy:

    ```bash
    ssh root@178.156.149.251 "pm2 logs cryptobot --lines 30 --nostream"
    ```
  </Step>
</Steps>

## Key rules

<Warning>
  **Never edit `dist/` directly.** The `dist/` folder is generated from TypeScript source and will be overwritten the next time `./deploy.sh` runs. All changes must be made in the `.ts` source files.
</Warning>

- All logic lives in `.ts` files — treat `dist/` as an artifact.
- Run `./deploy.sh` after every change; there is no hot-reload on the VPS.
- The deploy script uses `--update-env` on pm2 restart, so environment variable changes take effect automatically.

## VPS file locations

| Path | Purpose |
|---|---|
| `/opt/cryptobot/` | Production codebase root |
| `/opt/cryptobot/dist/` | Compiled JavaScript (do not edit) |
| `/root/.pm2/logs/cryptobot-out.log` | stdout log |
| `/root/.pm2/logs/cryptobot-error.log` | stderr / crash log |
